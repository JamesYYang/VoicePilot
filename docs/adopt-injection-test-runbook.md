# 采纳写回真机验证手册（Plan 2B）

> 目的：验证「点采纳 → 文本写回快捷键触发那一刻的前台窗口」在真机上真的可用，并把**失败**也验成可感知的。
> 上游：`docs/superpowers/specs/2026-09-13-adopt-injection-design.md`（设计）；PRD F5 / §4.3 / §8 M5-A；`docs/superpowers/specs/2026-09-12-trial-feedback-design.md` §2.4（降级条件）。

## 一、先读这一节：现在的验证状态

**自动化自测全绿 ≠ 功能可用。** 本功能的成功判据是「目标窗口确实到了前台」，这条只能真机验（设计 §3、§6）。

| 项 | 状态 | 证据 / 说明 |
|---|---|---|
| `koffi@3.2.1` 预编译安装（无编译器步骤） | **已实测（Windows 开发机）** | `koffi.load('user32.dll')` 成功，`GetForegroundWindow()` 返回真实 HWND |
| `uintptr_t` / `uint64_t` / `intptr_t` 返回值类型 | **已实测（Windows 开发机）** | 返回 **`number`**；`void*` 返回 `bigint`。HWND 直接用 `!==` 比较 |
| asarUnpack 新 glob 让 `.node` 移出 asar | **已实测（Windows 开发机，A/B）** | `electron-builder --win --dir` + `-c.asar.smartUnpack=false`：旧 glob `node_modules/koffi/**` 不命中（koffi 3.x 的原生二进制在 `@koromix/koffi-<plat>-<arch>/`），`.node` 留在 asar 内；新 glob `@koromix/**` 命中，asar 缩小约 1.04 MB，产物落在 `app.asar.unpacked/node_modules/@koromix/koffi-win32-x64/win32_x64/koffi.node`（1,036,800 B） |

| **整个 macOS 实现**（5 个 `objc_msgSend` 声明、`AXIsProcessTrusted` 符号解析、`frontPid()`、自守、`activateWithOptions:`、`CGEventPost`） | **未验（需 Mac 真机）** | macOS 上从未执行过 |
| **打包版能否 `dlopen` 外置的 `.node`**（Win / Mac arm64） | **未验** | 上面的 A/B 只证明文件**移动了**，没证明应用能**加载它** |
| **A2 回归**（新增 `start()` 时同步捕获后，聆听三态仍不抢焦点） | **未验（真机）** | 界面自测覆盖不到真实焦点 |
| `SetForegroundWindow` 被前台锁拒绝的频率、`AttachThreadInput` 兜底是否够用 | **未验** | `GetWindowThreadProcessId(hwnd, null)` 只在开发机上探过一次，未抛异常、返回了合理线程 id |

## 二、前置准备

### 起应用

```bash
cd app
npm install          # 首次
npm start            # 开发模式（vite build + electron .）
```

打包版见「用例 7」，**打包版要单独跑一遍**，理由见「用例 7 → 为什么必须单独测」。

### 权限

| 平台 | 需要的权限 | 用在哪 | 何时弹 |
|---|---|---|---|
| Windows | **无** | 合成按键不需要额外授权 | — |
| macOS | **辅助功能**（隐私与安全性 → 辅助功能） | `CGEventPost` 发 Cmd+V；`AXIsProcessTrusted` 检查 | 不会弹，需手动勾上 VoicePilot / 开发模式下的 Electron 或终端 |

> macOS 上「全局快捷键」本来就需要辅助功能权限。本功能的授权**复用同一项**，F12 引导不需要扩（设计 §4.2）。

### 触发快捷键

macOS `⌥Space`；Windows `Ctrl+Shift+Space`（F7 可配，若改过以实际为准）。

### reason → 提示文案对照表

失败时悬浮条**不关闭**，按 `reason` 显示下列文案（三语齐全，此处列 zh-CN）。记录时请**照抄提示原文**，它直接对应内部 `reason`：

| `reason` | zh-CN 文案 | 触发条件 |
|---|---|---|
| `no-target` | 自动写回失败，已复制到剪贴板，请手动粘贴 | 触发那一刻没捕获到前台窗口（如焦点在桌面） |
| `activate-failed` | 自动写回失败，已复制到剪贴板，请手动粘贴 | 置前后回读前台窗口 ≠ 目标（置前被系统拒绝） |
| `send-failed` | 自动写回失败，已复制到剪贴板，请手动粘贴 | 合成按键这步抛异常 |
| `stale` | 目标窗口已关闭，已复制到剪贴板，请手动粘贴 | 目标窗口/进程已不存在 |
| `permission` | 未获得辅助功能权限，无法自动写回。已复制到剪贴板，请手动粘贴 | 仅 macOS：未授予辅助功能 |
| （复制本身失败） | 复制失败，请重试 | 写剪贴板就失败了，**不会**尝试注入 |

## 三、用例 1：macOS 未授权 → 授权 → 成功（仅 macOS）

这条路径是 macOS 独有的，也是「失败可感知」的样板。

1. 打开「系统设置 → 隐私与安全性 → 辅助功能」，**取消勾选** VoicePilot（若已勾上）。
2. 在文本编辑器里点好光标 → 按快捷键 → 说一句话 → 等进入 `reviewing` → 点「采纳」。
3. **期望**：
   - 剪贴板已被写入（复制这步先成功）；
   - 悬浮条**不关闭**；
   - 出现提示「未获得辅助功能权限，无法自动写回。已复制到剪贴板，请手动粘贴」。
4. 去授权。**注意：这条提示本身是纯文本，没有按钮。** 深链在另一处（既有 F12 通道）：
   悬浮条点「打开应用」→ 设置 → 权限 → 「打开系统设置」按钮（`app/electron/ipc.js` 的 `vp:permission/open-settings`）。
   > 深链 URL 用的是经典写法 `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`。macOS 13+ 系统设置改版后若跳不到辅助功能页，**这也是要记的坑**（备用写法见该 handler 注释）。
5. 授权后：回到目标应用、**不重启 VoicePilot**，再点一次「采纳」。
6. **期望**：文本出现在目标应用，悬浮条关闭。
   - ⚠️ **待验**：授权后是否需要重启应用 / 重新触发一次快捷键才生效。`AXIsProcessTrusted()` 理论上实时反映 TCC 状态，但**没实测过**。若还提示 `permission`，说明进程内缓存了状态，如实记录。

**记录**：是否出现提示、提示原文、深链是否跳到正确页面、授权后第一次点采纳是否就成功。

## 四、用例 2：目标应用矩阵（Windows 与 macOS 各一遍）

对**每一个**应用重复：打开并点进输入位置 → 按快捷键 → 说一句**中英数混排**的话（例如「明天下午三点，和 Acme 团队过一下 Q3 预算」）→ 停止 → 等 `reviewing` → 点「采纳」。

| # | 目标应用 | Windows | macOS | 备注 |
|---|---|---|---|---|
| 2.1 | 记事本 / TextEdit | | | 基线，应当成功 |
| 2.2 | 浏览器输入框（地址栏与网页 `<textarea>` 各一次） | | | |
| 2.3 | 终端（Windows Terminal / PowerShell；macOS Terminal / iTerm） | | | **见下方「终端的特殊预期」** |
| 2.4 | Office（Word 或 Excel，任一） | | | 未装就记「未测（无 Office）」 |

每个格子记录三件事：
1. 文本**是否真的出现在目标输入位置**；
2. 悬浮条**是否关闭**；
3. 若失败，提示是哪一条（照抄原文）。

### 终端的特殊预期（重要）

成功判据是「**窗口到了前台**」，不是「粘贴被消费了」（设计 §3）。所以终端上完全可能出现：

> 悬浮条**关闭了**（判成功），但文本**没有**落进终端。

这不是 bug，是设计 §0 已接受的代价 2 与 5（终端粘贴行为不一致 + 静默失败不可检）。**照实记录成「误报成功（悬浮条关闭但未写入）」**，不要当成新缺陷去修 —— 本计划不含终端逐字注入回退（见第十三节「已接受的代价」）。

## 五、用例 3：管理员权限窗口（仅 Windows）

**这是已接受的代价，验的是「失败可感知」，不是「能写进去」。**

1. 用**管理员身份**运行记事本（任务管理器 → 运行新任务 → 勾「以系统管理权限创建此任务」→ `notepad`）。
2. 在管理员记事本里点好光标 → 按快捷键 → 说一句 → `reviewing` → 点「采纳」。

**期望**（二选一，都算可接受，但必须记录是哪一种）：

- **A. 失败且可感知（期望的形态）**：悬浮条**不关闭**，提示可见（多半是 `activate-failed` 或通用文案）；剪贴板里**仍有这段文本**；用户手动按 Ctrl+V（真人按键不受 UIPI 限制）能粘进管理员记事本。
- **B. 误报成功**：悬浮条关闭了，但文本没进去。这说明 `SetForegroundWindow` 对管理员窗口成功了、而合成 Ctrl+V 被 UIPI 丢弃 —— 属设计 §0 代价 1 的直接后果，**记录即可，不修**。

**务必确认**：无论 A 还是 B，剪贴板里都是这段文本（「不还原」的收益就在这里 —— 失败最多是「没省一步」）。

## 六、用例 4：A2 回归（焦点，Windows 与 macOS 各一遍）

引入写回时在 `SessionMachine.start()` 里加了**同步捕获前台窗口**的调用（在 `#setState('warming')` 之前）。必须确认这没有把焦点抢回来。

1. 打开记事本 / TextEdit，点好光标。
2. **持续打字**（别停），中途按快捷键触发听写，说一句话，再按一次停止。
3. 观察 `warming` → `listening` → `draining` 全程。
4. 等进入 `reviewing` 后点「采纳」。

**期望**：
- 聆听三态期间**焦点不跳**，前台仍是原输入框，**打字继续落进原输入框**；
- 采纳成功后，识别文本被追加到原窗口（同一输入框）。

> `reviewing` 态本身是可聚焦的（09-12 设计 §0 代价 1），所以**点击悬浮条**会让焦点转移属正常。这里验的是**不点悬浮条的情况下聆听三态不抢焦点**。

## 七、用例 5：剪贴板语义 —— 从不还原（Windows 与 macOS 各一遍）

**明确验这一条**，因为它是与 09-12 设计**相反**的决策（09-12 §2.2 原本要求「备份用户剪贴板 → … → 还原」；2026-09-13 改为从不还原，见设计 §0）。

1. 先往剪贴板放一个哨兵串，例如 `SENTINEL-12345`。
2. 触发听写，说一句话，点「采纳」。

**期望（成功路径）**：采纳后剪贴板内容 = **那段识别/润色文本**，**不是** `SENTINEL-12345`（哨兵被覆盖且不恢复）。

**期望（失败路径）**：制造一次失败（未授权 / 管理员窗口），确认剪贴板里**仍是那段文本**，可直接手动粘贴。

## 八、用例 6：最小化 / 已关闭的目标窗口

### 6a 目标窗口被最小化

1. 记事本输入框里打字确认焦点 → **最小化**记事本 → 在别的窗口按快捷键 → 说一句 → 点「采纳」。

**期望（仅 Windows）**：记事本被 `SW_RESTORE` 还原并置前，文本落进去（设计 §4.1 的 `IsIconic` → `ShowWindow`）。
**macOS 无此期望**：实现里没有反最小化调用（只调 `activateWithOptions:`），请如实记录实际行为作为观察结果，不要拿上面的期望判失败。
若失败，记录提示是哪条 —— `stale` / `activate-failed` **都算「可感知失败」**，只要悬浮条不关闭、剪贴板留着文本。

### 6b 目标窗口在采纳前被关掉

1. 记事本输入框点好光标 → 按快捷键 → 说来话 → **在点采纳之前关掉记事本** → 点「采纳」。

**期望**：提示「目标窗口已关闭，已复制到剪贴板，请手动粘贴」，悬浮条**不关闭**。
判 `stale` 的机制不同：Windows 走 `IsWindow` 为假；macOS 走 `runningApplicationWithProcessIdentifier:` 返回 nil。

⚠️ **macOS 特别观察项**（**按实现推断，未验**）：如果关掉的是**单个窗口**而应用进程还在，`runningApplicationWithProcessIdentifier:` 仍会返回非 nil → 不会判 `stale`，会走「置前成功 → 发键」但文本无处可落。**这条是从代码推断的，没在任何机器上跑过**，请按上面的步骤实测并记录实际表现。

## 九、用例 7：打包版专项（Windows 与 macOS 都要）

### 为什么必须单独测

- **asar**：开发模式下 `.node` 直接从 `node_modules` 加载，**绕过 asar**。开发模式通过**不能**证明打包版能加载。
- **macOS 激活行为**：开发模式从终端起的是 `Electron.app`，前台本来就是它，很多「置前 / 焦点」问题在开发模式**根本看不出来**。既有教训：NSPanel 那个坑只在打包版暴露（见 `docs/macos-test-runbook.md` §七.2）。因此**用例 4（A2 回归）在打包版必须再跑一遍**。
- **macOS arm64 签名**：未签名 / adhoc 的 `.node` 能否 `dlopen`，只在打包版才暴露。

### Windows

```bash
cd app
npm run dist:win
```

从产物启动（`release/win-unpacked/VoicePilot.exe`，或 NSIS 安装后的程序）。

① **查 `.node` 在 asar 外**：
```
release/win-unpacked/resources/app.asar.unpacked/node_modules/@koromix/koffi-win32-x64/win32_x64/koffi.node
```
存在即说明 `asarUnpack` 的 `@koromix/**` glob 生效。

② **比「文件在」更硬的证据**：应用能起来且**不报 koffi 加载错误**，并在打包版里把用例 2.1（记事本）跑通一次。

### macOS

```bash
cd app
npm run dist:mac
```

从 `VoicePilot.app`（`release/mac-arm64/` 下的目录产物或 dmg 安装后）启动，**从 Finder 启动**，不要从终端起。

① **查 `.node` 在 asar 外**：
```
VoicePilot.app/Contents/Resources/app.asar.unpacked/node_modules/@koromix/koffi-darwin-arm64/<子目录>/koffi.node
```
（子目录名以实际产物为准。）

② **未签名 / adhoc 的 `.node` 能否 `dlopen`** —— **这是头号问题**（设计 §5）。
若启动即报 koffi 加载失败，修法是在 `afterPack` 钩子里对 koffi 的 `.node` 做 adhoc 签名（`codesign -s -`）。

③ ①② 通过后，把用例 1–6 的 **Mac 部分**在打包版上再跑一遍。

### 降级条件（触发就要回头改决策，不要硬上）

**① ② 任一不成立** → 触发 `docs/superpowers/specs/2026-09-12-trial-feedback-design.md` §2.4 的降级：**退回纯剪贴板方案**（去掉「采纳」，或把它降级为「复制并提示手动粘贴」）。
按本项目惯例：先回头改设计文档的决策表，再动实现。

## 十一、结果怎么回报

每个用例记录：

1. **环境**：平台 + 机型 + 系统版本（如 Windows 11 23H2 / MacBook Air M2 macOS 15.x）、**是否打包版**；
2. **预期 vs 实际**：只说发生了什么，不要写「应该」；
3. **失败时的提示原文**（照抄，它直接对应 `reason`）；
4. 涉及输入效果的，附一句含中英数的实测文本。

## 十二、常见坑

- **点采纳毫无反应**：先看是不是复制这步就失败了（提示「复制失败，请重试」）。若连提示都没有，多半是 IPC 桥没就绪，看主进程日志里 `[采纳] 写回通道失败`。
- **macOS 上提示 `permission` 反复出现**：辅助功能没勾对对象。开发模式要勾的是启动它的**终端**（或 Electron），打包版勾的是 **VoicePilot.app**。授权后若仍报，试重启应用。
- **macOS 深链跳不到辅助功能页**：系统设置改版导致，换 `x-apple.systempreferences:com.apple.settings.privacy?Privacy_Accessibility` 再试，并记录系统版本。
- **文本粘进了错误的窗口**：这是最严重的一类，请**立即记录当时的前台窗口是什么**。设计上发键前必须先回读确认目标已在前台（`app/electron/inject/index.js` 的编排），自测覆盖了这条顺序，但真机若复现说明编排被绕过。
- **打包版和开发模式表现不一致**：先怀疑 asar / 激活策略 / 无 `.env`，不要先怀疑注入逻辑本身。

## 十三、已接受的代价（不要当缺陷重开）

以下四条在设计阶段就已拍板接受，**看到不要当 bug 报**（依据：设计 §0）：

1. **管理员权限窗口（Windows UIPI）** 收不到非提权进程的合成按键 → 静默失败或可感知失败；
2. **终端与部分特殊控件的粘贴行为不一致** → 不做逐字注入回退，用户手动粘；
3. **中文 IME 组字态可能吞掉 Ctrl+V** → 本期不检测、不清空合成状态；
4. **剪贴板从不还原**，用户中途切了应用仍写回旧窗口（目标在触发那刻固定）。

若将来试用范围变化（例如必须支持管理员窗口），**先回头改设计 §0 的决策表，再动实现**。
