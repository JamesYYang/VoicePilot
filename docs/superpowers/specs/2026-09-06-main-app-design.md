# 主应用（Studio）设计

> 状态：已确认，待实现（M4）
> 日期：2026-09-06
> 关联：PRD §1.2 两个形态、§4.4 润色流程、§5.4 润色、§5.5 本地历史、功能 F5/F6/F7/F8

## 1. 定位

主应用（Studio）是 VoicePilot 的第二个形态，与悬浮条（Mini）互补：

| | 悬浮条 Mini | 主应用 Studio |
|---|---|---|
| 触发 | 全局快捷键 | 悬浮条「润色」/ 托盘「打开主应用」 |
| 焦点 | 永不抢焦点 | 正常获取焦点 |
| 职责 | 实时听写 + 复制 + 润色入口 | 润色、场景/语气、历史回看与搜索、设置 |

**会话式**：润色是围绕"一次口述"的临时工作区，润色完关闭即结束。主应用不是笔记软件，不做长期文档管理。

## 2. 整体形态

- 普通窗口，**亮色**；悬浮条同步从深灰半透明换成**亮色半透明**，两处同一套色调
- 左侧**窄图标栏**：润色 / 历史 / 设置，三个图标
- 两个入口，默认落点不同：
  - **悬浮条「润色」** → 落在润色工作区，编辑器里预填本次口述原文
  - **托盘「打开主应用」** → 落在**历史**视图（无"本次口述"时，空编辑器无意义）

## 3. 润色工作区

```
┌──────────────────────────────────────────────┐
│ 场景 [下拉]   语气 [下拉]        [润色]        │
├──────────────────────────────────────────────┤
│ 原文（可编辑 textarea）                        │
│  ...                                          │
├────────────────────────┬─────────────────────┤
│ 原文（并排，仍可编辑）    │ 润色结果（流式逐字） │
├────────────────────────┴─────────────────────┤
│      [采用]  [复制]  [关闭]                    │
└──────────────────────────────────────────────┘
```

- 顶部工具条：场景下拉 + 语气下拉 + 「润色」按钮
- 原文编辑器：可编辑 textarea，识别错字可当场改
- 点「润色」→ 百炼文本模型 **流式** → 展开并排：左原文（仍可编辑，改动后可重新润色）、右润色结果逐字上屏
- 「采用」= 用润色结果替换编辑区原文；「复制」= 复制**编辑区当前内容**（采用前是原文，采用后是润色结果）；「关闭」= 结束本次会话
- 场景 4 类：邮件 / 即时通讯 / 文档 / 社媒；语气 4 类：正式 / 口语 / 简洁 / 热情
- 预设可新建、可编辑，存本地；**默认值由首次引导选择的职业驱动**（PRD §4.0）

## 4. 历史视图

- **列表 + 详情**主从结构：
  - 左侧：时间倒序列表，每条显示时间 + 原文前几十字 + 场景标签；顶部全文搜索框
  - 右侧：选中条目的完整原文 + 润色结果（如有）
- 存储：本地 SQLite，FTS5 全文搜索（中文用 **trigram** 分词，默认分词器对中文无效）
- 字段：时间、原文、润色后文本、场景、语气、音频时长（PRD §5.5）

## 5. 设置视图

- 快捷键（**可配置 + 冲突检测**，补上 M2 硬编码的缺口；Windows 上 `Alt+Space` 系统菜单、`Win+Space` 输入法切换不可用）
- 触发模式：按一下开始（toggle）/ 按住说话（hold）
- 开机启动
- 职业与词表（与首次引导联动）

## 6. 首次使用引导

- 首次启动弹一个小弹窗：选职业 → 加载对应预置词表；默认「通用」，可跳过
- 不占主导航；设置里可随时改
- 选择同时驱动 ASR 层（词表）与 LLM 层（场景默认值），一次选择两处生效（PRD §4.0）

## 7. 数据流

1. 口述停止（进 reviewing）→ **原文立即写入历史**（无论用户是否复制/润色，PRD §4.3）
2. 用户点「润色」→ 原文带入润色工作区
3. 点「采用」→ 润色结果回写该条历史记录的"润色后文本"字段
4. 直接复制（不润色）→ 历史记录只有原文，无润色后文本

## 8. 技术要点

- **窗口**：复用现有 Electron 结构，新建一个可聚焦窗口，走 `app://` 协议的 `#studio` 路由（与现有 `#diag` 同一套 hash 路由机制，见 `app/src/main.tsx`）
- **状态与数据在哪个进程**：
  - 历史读写（SQLite）放**主进程**，渲染进程经 IPC 访问——延续 M2 的 Key/网络都在主进程的架构
  - 润色（LLM 流式）**直连百炼文本模型**，复用现有 `loadCredentials()`（`DASHSCOPE_API_KEY` + workspace，与 ASR 同一把 Key），开在**主进程**。模型：**DeepSeek-V4-Pro-0813**（2026-09-06 用户指定；**精确 model ID 需在 spike 中核实**，百炼控制台的模型 ID 是大写/日期后缀敏感）
- **并排显示**是刻意的：口述内容一旦被覆盖就找不回来，润色结果 LLM 可能改变原意，所以显式「采用」才替换，原文始终保留在历史里（PRD §4.4）

## 9. 非目标（本期不做）

- 翻译（F14）、导出 PDF（F15）—— v1.1
- 云端同步、多设备
- 富文本排版（原文是纯文本，不是 Word）
- 账号体系、付费

## 10. 开放风险

- **模型 ID 待核实**：`DeepSeek-V4-Pro-0813` 是用户指定的百炼文本模型，动手前需在百炼控制台/API 里确认精确的 model ID 字符串（含版本日期后缀），并实测其流式输出可用
- **中文全文搜索分词**：FTS5 trigram 方案需实测效果与体积
- **悬浮条换亮色**：半透明亮色在白色背景（如 Word 文档）上可读性需实测，可能要加描边或阴影兜底
