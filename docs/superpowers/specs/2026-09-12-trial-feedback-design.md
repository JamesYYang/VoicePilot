## 0. 已拍板的关键决策

| 决策 | 结论 | 依据 |

### 明确接受的代价（不修）

1. **"不抢焦点"从全程保证降级为"仅聆听期保证"**。reviewing 期窗口可聚焦，用户点击编辑时才真正拿焦点。这是"悬浮条内编辑"无法回避的代价（`app/electron/main.js:169` 的 `focusable:false` 是 A2 的基石）。
2. **注入有天花板**：管理员权限窗口（Windows UIPI）收不到非提权进程的输入；部分终端/特殊控件粘贴行为不一致。这些场景回退为"已复制到剪贴板，请手动粘贴"。
3. **flash 可能比 pro 弱**。反馈原文是"要更好的模型"，但用户选择 flash（速度优先）。质量若下降属已接受范围内。
4. **未做前置 spike**，原生依赖（取前台窗口 / 置前 / 发按键）可能在实现中才发现不可用。此风险由「实现第一步先验证依赖」承接，不假装不存在。

> 以上 1–3 是用户拍板的权衡，**不要在后续 review 里当缺陷重开**。若将来试用范围或形态变化，先回头改这里。

## 2. 采纳写入（最重的一块）

> **⚠️ 本批（Plan 2A）只做回退路径。** 已交付的是 §2.3 的失败回退形态：点「采纳」＝ 取「当前有效文本」复制到剪贴板 + 提示「已复制到剪贴板，请手动粘贴（自动写回尚未实现）」，**不还原剪贴板、不关闭悬浮条，也没有任何注入**。下面 §2.1–§2.2 的「取前台窗口 → 还原焦点 → 模拟粘贴 → 还原剪贴板」**成功路径尚未实现**，连同 `app/electron/inject/*` 一起留给 **Plan 2B**。§2.4 的原生依赖验证因此也还没开始。

### 2.1 时机

- **触发时**（快捷键 idle → warming 那一刻）：记录当前前台窗口句柄（Windows HWND；macOS bundle id + pid）。**在悬浮条出现之前**取，此时前台还是用户的工作应用。
- 会话内保持不变；采纳时用它作为写入目标。

### 2.2 采纳流程（成功路径）

```
备份用户剪贴板
  → 把「当前有效文本」写入剪贴板
  → 还原目标窗口到前台
  → 发 Ctrl+V (Win) / Cmd+V (mac)
  → 等一个短延时确保粘贴完成（实现时定，量级 50–150ms）
  → 还原用户剪贴板（仅成功时）
  → 落历史 → 关闭悬浮条
```

### 2.3 采纳流程（失败回退）

失败判据：无捕获窗口 / 置前失败 / 发键失败 / 目标是管理员权限窗口。

- **不还原剪贴板**（让文本留在剪贴板，用户可手动粘）；
- 悬浮条内明确提示「**已复制到剪贴板，请手动粘贴（自动写回尚未实现）**」；
- **不静默**（与现有剪贴板错误处理同一原则，`App.tsx:365-368`）。

### 2.4 原生依赖（实现第一步必须先落地）

Electron 无内置「取前台窗口 / 置前 / 发按键」能力，必须引入原生依赖。

- **Windows**：取前台窗口 + 置前 + 发送按键。
- **macOS**：激活任意 app + 发送 `Cmd+V`，**依赖辅助功能权限**（见 §9）。

> **实现第一步**：选定并验证依赖（如取窗口类库 + 发键类库，或自写最小 native），在 Win 与 Mac 上各手工验证一次「记住前台窗口 → 还原焦点 → 粘贴中文」。**这条不成立，整个 §2 退回纯剪贴板方案**（保留「复制」按钮，去掉「采纳」或将其降级为「复制并提示手动粘贴」）。
>
> **实际结果（Plan 2A）**：先按降级形态交付——保留「采纳」但降级为「复制并提示手动粘贴」（见本节顶部注）。依赖验证与注入一起留 Plan 2B，因此本节 §2.1–§2.2 目前仍是设计意图而非已实现行为。

## 3. 悬浮条交互重构

### 3.1 焦点策略（状态驱动）

| 状态 | `focusable` | 鼠标 | 内容 |
|---|---|---|---|
| idle | false | 穿透 | 不渲染 |
| warming / listening / draining | **false（不变）** | 穿透 | 只读展示 + 实时跟随滚动 |
| reviewing | **true** | 悬停恢复可点击 | 可编辑 + 按钮 + 高级折叠区（+ 润色分栏） |

- 进入 reviewing：`setFocusable(true)`（Windows）；macOS 需一并处理 panel 与激活策略。**不调用 `focus()`** —— 目标应用保持焦点，只有用户点击悬浮条才真正拿焦点。
- 离开 reviewing：恢复 `focusable:false`。
- 状态源头仍在主进程（`app/electron/session/machine.js`），渲染进程只订阅（沿用现有约定）。

### 3.2 reviewing 态布局

- **文本区**：变为**可编辑输入区**，是文本的唯一真源。
- **按钮**：`润色` / `复制` / `采纳` / `打开应用` / `关闭`。
- **高级折叠区**（默认折叠）：`场景` / `语气` 两个下拉，**只能选预设**，值读自主应用 store（`app/electron/store.js`，预设管理在 `app/src/studio/PresetManager.tsx`）。默认取上次使用值。
- **点「润色」后**：上半保持可编辑原文，下半为流式润色结果（只读）。
- **采纳**：取「当前有效文本」——有润色结果送润色结果，否则送编辑后原文。**本批只复制到剪贴板 + 提示「已复制到剪贴板，请手动粘贴（自动写回尚未实现）」，不关闭悬浮条**；「写回目标应用 → 落历史 → 关闭」是 Plan 2B 的目标形态，尚未实现（见 §2 注）。
- **复制**：送同一份「当前有效文本」→ 关闭（保持现有行为）。
- **打开应用**：`openStudio`，打开主应用（历史 / 设置 / 预设管理）。
- **关闭**：回写编辑后的文本 → 关闭（与 §7 一致：采纳/复制/关闭都更新同一条历史）。

### 3.3 尺寸

- 现有上限 420（`app/electron/main.js:45`）装不下「编辑区 + 5 按钮 + 折叠区 + 润色分栏」。**上限先取 620**，仍不够再调。
- 现有自动长高逻辑（`App.tsx:331-343`）随布局调整；保持底边固定的向上生长。

## 4. 分段

**改为「每个定稿句单独一行」**，不再按停顿分自然段。

原「按停顿分自然段」判据（阈值 = 近期句间停顿中位数 × 2.5，下限 1200ms）已证伪，无法使用：

- 正常说话节奏下阈值永远够不着：均匀 1000ms 停顿 → 阈值 2500ms，小幅 400ms 停顿 → 阈值 1200ms，两种情况都不会触发换行。
- 且判据依赖已积累的停顿样本，**头 4 个定稿句之前不可能分段**。

因此去掉阈值与停顿测量，判据简化为：每个 `sentence_end` 定稿句各占一行。原始帧字段已核实齐全（`begin_time` / `end_time` 均在），但新规则不再需要它们。

## 5. 润色

- 模型换 `deepseek-v4-flash-0731`（`app/electron/llm/polish.js:5`）。
- 润色链路从"独立 Studio 窗口"改为**悬浮条内运行**：复用现有 `startPolish` IPC 与流式事件（`onPolishDelta` / `onPolishDone` / `onPolishError`），渲染到下半栏。
- 场景/语气读自主应用 store，悬浮条只读不写。

## 6. 快捷键自定义（吸收 F7）

- 放进**主应用设置**（`app/src/studio/SettingsView.tsx`）：录制新键 + 冲突检测。
- 冲突检测：`globalShortcut.register` 返回 false 即失败，提示用户换一个。
- 改键流程：`unregister` 旧的 → `register` 新的 → 写 store；失败则回滚旧键。
- 默认仍为 Win `Ctrl+Shift+Space` / macOS `Alt+Space`（`app/electron/main.js:418`）。驱动同一个 toggle。

## 7. 历史

现状：进入 reviewing 时先落库一次（`App.tsx:302-310`）。加了编辑后，若用户改了再采纳，历史会停在未编辑版本。

**决定**：保持先落库（防丢失），采纳/复制/关闭/打开应用时若文本有变化，则**更新同一条**（按 `historyId`）。

- 需要新增「更新历史」IPC（现有只有 `vp.historySave`）。实现时先确认 store 侧是否已有可复用的更新入口，没有就新增。**（Plan 2A 已落地：新增 `vp:history/update-text` + store `updateHistoryText`，见 §1。）**

## 8. 错误与回退

| 场景 | 表现 |
|---|---|
| 采纳注入失败（**本批「采纳」恒走此行**：没有注入，直接复制 + 提示） | 悬浮条提示「已复制到剪贴板，请手动粘贴（自动写回尚未实现）」，**保留剪贴板**，不关闭 |

| 无捕获目标窗口 | 同采纳注入失败 |
