# macOS 测试手册（M1 采集诊断 + 端到端）

> 目的：Mac 到手后，用与 Windows 完全相同的流程验证采集链路，判断 macOS 是「Web Audio 直接过」还是「要改原生采集 helper」。
> 背景见 PRD §5.2 / §5.2.1 / §5.2.2 与风险 R1。

---

## 一、为什么 Mac 是硬阻塞

PRD §5.2 要求 Windows 与 macOS **各出一份实测数据**，且「图时钟是否漂移、端到端延迟」必须真机验证。领导 2026-09-05 在 MacBook 上体验明显劣于 Windows（「只能识别到几秒前说的话」），疑因两个机制叠加：

1. 老 demo 的整数抽取 bug（已修，改小数比插值）
2. **图的水槽接 `ctx.destination` 时，图由输出设备时钟拉动，与采集设备不同源**（Windows 实测慢 0.45%，换软件水槽后残余 −0.005%）

macOS 上蓝牙耳机是常态，输入/输出不同源只会比 Windows 更普遍。**所以拿到机器第一件事就是跑下面的测试一**，用同一把尺子量。

---

## 二、前置准备（一次性）

```bash
# 1. 装 Node 22+（package.json engines 要求 >=22）

# 2. 拉代码
git clone <仓库地址>
# 或已有代码则 git pull 同步

# 3. 装依赖
cd voicepilot/app
npm install

# 4. 配 .env（gitignored，不会随仓库下来，需在 Mac 上手动建）
cd ..                       # 回到仓库根
cp .env.example .env
# 填入两个值（百炼控制台获取）：
#   DASHSCOPE_API_KEY
#   DASHSCOPE_WORKSPACE_ID  —— 业务空间 ID，不是 API Key
```

> `.env` 只在**测试二（端到端）**走 ASR 时才需要；测试一（采集诊断）不用它。

### macOS 权限（都要在「系统设置 → 隐私与安全性」里给）

| 权限 | 用在哪 | 何时弹 |
|---|---|---|
| 麦克风 | 采集音频 | 首次运行时弹，必须点「允许」 |
| 辅助功能 | 全局快捷键 `⌥Space` | 不会弹，需手动去设置里勾上终端/Electron |

## 三、测试一：M1 采集诊断（最关键，先做这个）

```bash
cd app
VP_OPEN_DIAG=180000 npm start
```

**它会自动做**：打开诊断窗口 → 采集 3 分钟 → 停止 → 导出 WAV → 把结果 JSON 打到终端。

**全程不用说话**，静音跑即可——采样率/字节率/时钟漂移这些指标跟说没说无关。

跑完终端里会有一行以 `[渲染] [M1] {...}` 开头的 JSON，这就是结果。也可以点诊断窗口右下角「复制结果 JSON」按钮，复制出格式化更好的同一份数据。

### 判定标准（同一把尺子）

| 指标 | 合格线 | 不合格意味着 |
|---|---|---|
| 输出字节率 | 32000 B/s，偏差 ≤ **±2%** | 重采样比例错了，ASR 听不到正常语速 |
| 图时钟速率 | 1.000000 ± **0.001** | 图由输出设备时钟拉动（双时钟不同源），越说越滞后——**macOS 头号嫌疑** |
| 掉帧（音频空洞） | 必须 = **0** | 渲染线程没赶上，音频有空洞，ASR 漏字 |
| 批处理滞后变化 | ≤ **±200ms** | 主线程追不上实时，滞后持续增长 |

> 「掉帧 = 0」但「图时钟速率偏」= 音频被整体拉伸千分之几，人耳听不出、ASR 不敏感，**无害可过**；「掉帧 > 0」才是缺陷。这两行要一起看。

## 四、测试二：端到端（验证领导遇到的「只能识别到几秒前」）

```bash
cd app
npm start
```

**前置**：`.env` 已配好 + 麦克风权限 + 辅助功能权限（`⌥Space` 快捷键需要）。

**操作**：按 `⌥Space` 说话，看悬浮条是否实时出字（灰字草稿 → 停顿定稿转白字）。

### 重点：内置麦克风和蓝牙耳机各测一轮

领导的 MacBook 疑因蓝牙耳机（输入/输出时钟不同源）。**两种输入设备分别测一轮并对比**，才能定位是不是蓝牙的问题：

1. 内置麦克风：跑一遍测试一 + 说几句话看延迟
2. 蓝牙耳机：同样再来一遍

---

## 五、结果怎么回报

**直接贴**终端里那行 `[M1] {...}` JSON（或「复制结果 JSON」按钮的内容）。

**另外必须附带三件事**：

1. Mac 型号 + macOS 版本（如 MacBook Air M2 / macOS 15.x）
2. 用的是哪个麦克风（内置 / 蓝牙耳机型号）
3. 有没有报错（麦克风权限被拒、快捷键没反应等）

这三条是判断「是不是蓝牙双时钟不同源」的关键，JSON 里只有指标、没有硬件背景。

---

## 六、常见坑

- **终端没出现 `[M1]` 行**：多半是麦克风权限被拒。看诊断窗口有没有红色报错，去系统设置补授权后重跑。
- **快捷键没反应**：`⌥Space` 需要辅助功能权限，手动去「隐私与安全性 → 辅助功能」勾上。
- **端到端没字 / 报 key 相关错**：`.env` 没配或字段填错（`DASHSCOPE_WORKSPACE_ID` 是业务空间 ID，不是 API Key）。
- **蓝牙耳机延迟明显**：这本身就是要抓的现象，把两轮 JSON 都贴回来即可，不用现场判断。
