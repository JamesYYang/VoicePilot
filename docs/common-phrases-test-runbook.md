# 常用语真机验证清单（F16）

> 目的：验证「按第二个快捷键 → 选择器拿到键盘 → 挑一条 → 走既有采纳写回」这条链路在真机上真的可用，并把**失败**也验成可感知的。
> 上游：`docs/superpowers/specs/2026-09-13-common-phrases-design.md`（设计）；PRD F16、§4.3（采纳写回）。
> 写法参照 `docs/adopt-injection-test-runbook.md`（采纳写回手册）：按症状与环境组织，**只写会踩的坑**。
>
> **两个清单的 macOS 部分在同一趟 Mac 上一起跑** —— 常用语复用采纳写回（`activateTarget`），macOS 的窗口激活 / 焦点 / 键盘结论是共用的。跑之前先按采纳写回手册验完。

## 一、先读这一节：现状与为什么只能真机测

自动化能覆盖的都在既有的几个 `VP_*_SELFTEST` 里（本轮**未新增 selftest 入口**，只扩了既有套件）。**本文件只列自动测不到的**：键盘输入、窗口激活、全局快捷键、真实写回。

| 项 | 状态 | 说明 |
|---|---|---|
| 状态机 `phrases` 态（进出、`origin`、不落历史、`onAudioFrame` 早退） | **已自动测** | `VP_SM_SELFTEST`；含「在条获得焦点**之前**捕获目标」「闸门在拆状态之前取样」两条顺序断言 |
| store 的 phrases CRUD 与 `used_at` 排序 | **已自动测** | `VP_STORE_SELFTEST`；含旧库自动建表断言 |
| 两个快捷键槽位的注册 / 冲突 / 挂起 | **已自动测** | `VP_SHORTCUT_SELFTEST` |
| 选择器键盘映射（↑↓ / Enter / Esc / `preventDefault`）、标题截断、Studio CRUD | **已自动测** | `VP_UI_SELFTEST`（跑前必须 `npm run build`，否则跑的是旧产物） |
| `activateTarget` 只置前、不发键 | **已自动测** | `VP_INJECT_SELFTEST`（与采纳写回共用同一原语） |
| **选择器在真机上是否真的拿到键盘输入** | **未验（最高风险）** | 见用例 1。Windows 与 macOS 各一遍；macOS 的 `type:'panel'` 面板能否收键盘从未在任何机器上执行过 |
| **关掉选择器后的焦点归还** | **未验** | 见用例 2。含闸门 `bar.isFocused()` 是否如实（macOS 面板若恒报 `false`，表现是「静默不归还」） |
| **焦点类结论必须在打包 `.app` 上复验** | **未验** | 开发模式从终端起的是 `Electron.app`，很多激活 / 焦点问题**根本看不出来**（既有教训：NSPanel 那个坑只在打包版暴露，见采纳写回手册用例 7）。用例 1 / 2 / 6 在 macOS 打包版必须再跑一遍 |
| 用例 3–7 | **未验** | Windows 侧现在就能全验；macOS 随采纳写回那趟一起 |

> **自动化全绿 ≠ 功能可用。** 选择器的全部价值就是键盘驱动；用例 1 不成立，等于设计前提被证伪。在汇报里一律写「未验」，打勾前不得声称 F16 完成。

## 二、前置准备

### 起应用

```bash
cd app
npm run build && npx electron .
```

- **先按 `docs/adopt-injection-test-runbook.md` 验完采纳写回**（本期复用它；macOS 那轮与它合并执行）。
- **先存两条常用语**：说一句话 → 等进入 `reviewing` → 点条头的书签图标 → 条内提示「已存为常用语」。
- macOS 上全局快捷键需要**辅助功能权限**（权限对象与授权步骤见采纳写回手册「权限」一节，本功能复用同一项，F12 引导不需要扩）。

### 触发快捷键

| 槽位 | Windows 默认 | macOS 默认 | 说明 |
|---|---|---|---|
| 主快捷键（听写） | `Ctrl+Shift+Space` | `⌥Space` | F1 / F7，可配 |
| **第二个快捷键（常用语）** | `Ctrl+Alt+Space` | `Alt+Shift+Space` | F16，设置页「常用语快捷键」可改 |

若改过以实际为准。快捷键状态与冲突文案（照抄原文，它直接对应内部结果）：`该快捷键已被占用，请换一个` / `这个按键不能用作快捷键，请换一个`。

## 三、用例 1：选择器能拿到键盘（**最高风险**，spec §6 风险 1）

这条不成立，**键盘驱动的设计前提就被证伪**。

1. 光标放进记事本 / Word，按**第二个快捷键**。
2. **预期**：弹出选择器（悬浮条内），**搜索框已获得键盘焦点** —— 直接敲字就出现在框里，不需要先点一下。
3. 按 `↑` / `↓`：
   - **预期**：列表高亮移动，**且底层应用的内容没有跟着滚动 / 光标没有跟着移动**（`preventDefault` 生效）。
   - 高亮移到可视区外时应自动滚进视野（`scrollIntoView({ block: 'nearest' })`）。
4. 输入几个字过滤，按 `Enter`：**预期**选中高亮那条，条切到 `reviewing`、编辑区正文就是那一条。
5. **若不成立**（敲字没反应、必须先鼠标点搜索框、方向键带着底层应用滚动）：
   → **macOS 面板接受键盘输入的假设被证伪。停下来回到 `spec §6 风险 1` 改决策**（降级为纯鼠标点选），**不要在实现里默默绕过**。
   → 先区分是不是开发模式的问题：**必须在打包 `.app` 上再试一次**（开发模式从终端起的是 `Electron.app`，激活行为不同）。打包版也失败才算证伪。
   → 记录：平台、是否打包版、敲字无反应还是能敲但焦点在别处、`↑↓` 的实际表现。

**记录**：搜索框是否进态即获焦、能不能直接敲字、`↑↓` 是否被底层应用吃掉、Esc / Enter 是否响应。

## 四、用例 2：关掉选择器后焦点归还（spec §6 风险 3）

1. 光标在记事本里，按第二个快捷键打开选择器。
2. 按 `Esc`。
3. **预期**：选择器消失，**记事本重新是前台**，光标还在原位置，可直接继续打字。
4. **反向确认（验闸门）**：打开选择器后先点一下浏览器 —— 记事本退到后台、选择器**失去焦点但不会自动关闭**（失焦即关是本设计的排除项）。此时**再按一次第二个快捷键**（全局键不受焦点影响；**别用 `Esc`**：它此刻落在浏览器上，到不了选择器）。
   → **预期**：选择器关闭，且**焦点不应被拽回记事本**（归还前的闸门 `bar.isFocused()` 生效 —— 归还只在悬浮条确实持有焦点时发生）。
5. **回归**：以上任何一步之后，**任务栏都不应冒出 VoicePilot 按钮**
   （`setFocusable` 触发的 frame change 不能抵消 `skipTaskbar`；既有修法是在 `emit()` 里成对重申，见 09-11 的修复）。
6. **附加（spec §6 风险 4，平台行为待验）**：第 2 步改用**再按一次第二个快捷键** → 选择器同样应关闭，焦点同样应归还。全局快捷键通常优先于聚焦窗口，但这条要在真机确认。
7. **若不成立**：
   → 焦点没还回去（点了别处之后又被拽回来 = 闸门失效；从头就不还 = `isFocused()` 恒 `false` 或置前顺序失效）→ 记录是哪一种，并按 spec §6 风险 3 的 ①/② 分别标注（**不要**在实现里绕过）。
   → 任务栏冒出按钮 → 属 09-11 已修回归，明确记录并报。
   → **必须在打包 `.app` 上再跑一遍**再下结论（开发 / 打包不一致是这个项目的常态）。

**记录**：`Esc` 与「再按快捷键」两条关闭路径各一次、焦点是否归还、闸门为假时是否**不**归还、任务栏有无按钮。

## 五、用例 3：存一条 → 选一条 → 写回

1. 说一句话进入 `reviewing`，条头书签图标可点；点它 → 条底出现「已存为常用语」。
2. 关掉悬浮条，把光标放进 Word，按第二个快捷键。
3. 挑中刚存的那条 → **预期**弹回 `reviewing` 编辑区，正文就是那一条。
4. 点「采纳」→ **预期**文本插入 Word，光标留在 Word（走的是 F5 / §4.3 的既有采纳路径，目标窗口是**按第二个快捷键那一刻**捕获的前台窗口）。
5. 回 Studio 的「常用语」页确认：那条 `used_at` 更新了（下次排在最前，排序按 `COALESCE(used_at, created_at) DESC`）。
6. **若不成立**：
   → 编辑区不是那一条 → 记录（这是 `phraseText ?? fullText` 的 seed 问题）。
   → 采纳写回失败 → 先按采纳写回手册的「reason → 提示文案对照表」照抄提示原文，**不要**当成常用语缺陷；常用语只是复用那条通道。
   → 排序没变 → 记录（`used_at` 可能没写进去）。

**记录**：存入提示原文、选中后正文是否一致、采纳后文本落点与光标位置、`used_at` 是否刷新。

## 六、用例 4：常用语**不**进历史

1. 记下 Studio 历史页当前的条目数。
2. 用常用语走一遍「选中 → 采纳」。
3. **预期**：历史条目数**不变**（常用语采纳不属于「这次听写」）。
4. **对照**：正常听写一遍 → 历史条目数 +1。
5. **若不成立**：常用语进了历史 → 是渲染层落库 effect 的 `origin !== 'dictation'` 判据失效，明确记录（反复用同一条常用语会在历史里刷屏）。

**记录**：两次计数、对照是否 +1。

> 设计依据：常用语不是「这次听写」的产物，反复用会在历史里刷屏，而它自己已经有管理页（spec §2.3）。

## 七、用例 5：第二个快捷键的冲突与录制

在 Studio 设置页「常用语快捷键」块里操作：

1. 把它改成与**主快捷键相同**的值 → **预期**提示「该快捷键已被占用，请换一个」，**且主快捷键仍然可用**（按主键能正常开始听写）。
2. 改成某个已被**别的软件占用**的组合 → 同样提示，且**原短语键仍生效**。
3. 录制时按 `Esc` → **预期**退出录制且**不提交**（Esc 无修饰键，本表达不出，是显式的取消路径）。
4. 录制时按**纯修饰键**（如单独 `Ctrl`）→ **预期**提示「这个按键不能用作快捷键，请换一个」，且**留在录制态**等重按。
5. 改成功后**立刻按新键** → **预期**能打开选择器（不需要重启，注册即时生效）。
6. **若不成立**：
   → 冲突时把旧键也注销了 → 属回归（注册必须先成功再注销旧键），记录并报。
   → 冲突提示不改键但主键失效 → 同上，记录并报。
   → 改完要重启才生效 → 记录（`applyShortcut` 应在写入后立即注册）。

**记录**：四种输入（同主键 / 被占用 / Esc / 纯修饰键）各自的表现与提示原文，改键是否即时生效。

## 八、用例 6：A2 回归（不能被本期破坏）

1. 光标在 Word 里**持续打字**，按**主**快捷键开始听写。
2. **预期**：打字不中断、焦点不跳走（聆听三态 `warming` / `listening` / `draining` 仍不抢焦点）。
3. 只有按第二个快捷键（打开选择器）时才抢焦点（那是它的用途 —— 选择器要键盘）。
4. **若不成立**：聆听三态抢了焦点 → 这是本项目最硬的约束（A2），立即记录并报。
5. **打包版必须再跑一遍**（采纳写回手册用例 7 的同一条理由：焦点类问题开发模式看不出来）。

**记录**：聆听三态打字是否落进原窗口、是否只在第二个快捷键时才夺焦点、是否打包版。

## 九、用例 7：空态与边界

1. 在 Studio 里删光所有常用语，按第二个快捷键
   → **预期**显示「还没有常用语。在结果里点书签图标存一条。」（空库文案，与「没有匹配」的文案不是同一条）。
2. 存一条超长文本：**首行 > 40 字**（例如 41 个汉字）。
   - **预期**：选择器里**标题**被截断成 40 个字符并补 `…`（`PHRASE_TITLE_MAX = 40`，按码点算）。
   - 标题下方的**次行摘要是截断的预览**（把正文压成一行、取前 60 字符，spec §3.1），看到的不一定是全文 —— **这不是缺陷**。
   - 选中后进 `reviewing`，编辑区里的正文应是**完整**的那一条（截断只发生在标题与列表摘要的展示层）。
   - **若不成立**：标题没截断 / 没带省略号 → 展示层缺陷，记录；**编辑区正文被截断 → 数据层缺陷（存进去的就不是全文），严重，停下来报**。
3. 在 Studio 手写一条，**标题留空** → **预期**保存后标题显示为「未命名」（正文为空则保存不生效，按钮不做事）。
4. **若不成立**：空标题出现空白行 / 保存报错 → 记录。

## 十一、结果怎么回报

每个用例记录：

1. **环境**：平台 + 机型 + 系统版本（如 Windows 11 23H2 / MacBook Air M2 macOS 15.x）、**是否打包版**；

4. 涉及输入效果的，附一句含中英数的实测文本。

## 十二、常见坑

- **打开选择器后敲字没反应**：先确认是不是**窗口**没被激活（DOM focus 只决定键盘落在哪个元素上，窗口没被激活按键照样不来）。看主进程有没有走到 `bar.focus()`；若在 macOS 上，**先换成打包 `.app` 再判**。
- **选择器关了但焦点没还回去**：区分「从头就不还」（`isFocused()` 恒 `false` 或置前顺序失效）与「点了别处之后被拽回来」（闸门失效），两者根因不同。
- **任务栏冒出 VoicePilot 按钮**：`setFocusable` 的 frame change 抵消了 `skipTaskbar`，属 09-11 已修回归，记录并报。
- **采纳写回失败**：那一路的排障看采纳写回手册「常见坑」，**与常用语无关**，不要混为一谈。
- **打包版和开发模式表现不一致**：先怀疑激活策略 / asar / 无 `.env`，不要先怀疑选择器逻辑本身。

## 十三、已接受的代价与不含项（不要当缺陷重开）

以下在设计阶段就已拍板，**看到不要当 bug 报**（依据：spec §0.1 / §0.2）：

1. **无占位符 / 模板变量** —— 常用语是固定文本，不做变量替换；
2. **不与场景 / 语气绑定、不按场景分组** —— 它是纯文本库，采纳时场景 / 语气就是条底当前选的那套；
3. **不去重** —— 同一条文本可以存多次；
4. **不跨设备同步** —— 只在本地 `voicepilot.db`；
5. **不能从历史页把一条记录「提升」为常用语** —— 两个入口（录入后、润色后）都在悬浮条内；
6. **选择器不自动关闭**（失焦即关不做）—— 鼠标点到别处时保持打开，需 `Esc` / 再按一次快捷键 / 选中才关；
7. **撞键时启动期静默失败** —— 启动注册失败只打日志，悬浮条与设置页都不主动弹提示；逃生口是设置页重录同一个键会走到「该快捷键已被占用」。当前选择是**不做**「注册状态显示」。

若将来要扩，**先回头改 spec §0 的决策表，再动实现**。
