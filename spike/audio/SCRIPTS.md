# 录音念稿

照着念即可。**括号里的内容是提示，不要念出来。**

四段加起来约 3 分钟。每段念完单独存一个文件，念错了不用停，重录那一段就行。

## 念之前

- 安静房间，关风扇和音乐
- 麦克风距嘴 20–30cm，固定不动
- **正常语速、正常音量**，别刻意放慢或咬字——刻意表现会让测出的准确率虚高
- 手机或 Windows 录音机都行，录完用 `npm run normalize` 转格式

## 停顿时长参照

只有 `05-pauses` 需要控制停顿，另外三段自然念即可。

| 标注 | 大概多长 | 怎么把握 |
|---|---|---|
| 停 0.3 秒 | 快速换气 | 一口气没接上，赶紧吸一口 |
| 停 0.5 秒 | 正常换气 | 最自然的换气节奏 |
| 停 0.8 秒 | 明显停顿 | 想一下再继续 |
| 停 1.5 秒 | 长停顿 | 心里默数「一千零一」 |
| 停 2 秒 | 句尾 | 心里默数「一千零一、一千零二」 |

**停顿拿不准没关系。** 服务端会返回每句的时间戳，我们能从数据里反算出你实际的停顿有多长，不需要你卡得精准。

## 02-numbers（约 30 秒）· 验证 ITN

> ITN 是指 ASR 会不会把「二零二六年」自动转成「2026年」。这段专门测这个。

二零二六年九月三日出货三千二百件，客单价三十九块九，转化率百分之十二点五。上个月的广告花了八万六千四百块，带来了一千二百单，平均获客成本七十二块。目标是把退货率控制在百分之三以内，把复购率从百分之十八提到百分之二十五。双十一备货按去年的三倍准备，大概需要一百二十万的资金。

---

## 03-mixed（约 45 秒）· 中英夹杂

> 领导问的就是这个。用你真实会说的话，不要因为要念稿就改口。

这个 SKU 的 listing 需要重新优化一下，CTR 太低了，只有百分之零点八。我看了下竞品的 A+ 页面，图片和卖点都比我们清楚。先把主图的白底图换掉，再把五点描述里的关键词埋进去。另外 FBA 的库存只剩两周了，得赶紧补货，不然断货之后排名会掉得很厉害。广告这边 ACOS 已经到百分之四十五，太高了，先把表现差的 keyword 否定掉，把预算集中到转化率高的那几个词上。这个月的 GMV 目标还差三成，得靠 Prime Day 冲一波。

## 04-terms（约 40 秒）· 专有名词，验证热词

> 这段要先跑「无热词基线」，再跑「有热词」，两者的字准确率差就是热词的价值。

我们主要在 Amazon 和 Walmart 上卖，Temu 最近也开了店，Shopify 的独立站还在搭。竞品里 Anker 和 Shein 做得最好。运营这块，Kevin 负责广告，Anna 负责供应链。目前 FBA 的库存周转还不错，但 ACOS 一直压不下来。下周要跟深圳的供应商确认新一轮的报价，顺便把 SKU 编码重新梳理一遍。对了，TikTok Shop 的达人带货我们也想试试，先找三个达人做测试。

---

## 05-pauses（约 60 秒）· 断句阈值

> 这段决定 `max_sentence_silence` 能不能从默认 1300ms 调到 400ms。
> 每句**中间**按标注停一次，**句末统一停 2 秒**。停顿标注不要念出来。

我们这个季度（停 0.3 秒）重点是把退货率降下来。（停 2 秒）
客服那边（停 0.3 秒）已经把话术整理好了。（停 2 秒）
仓库的库存（停 0.5 秒）下周会补一批过来。（停 2 秒）
广告的预算（停 0.5 秒）我建议先不加。（停 2 秒）
这次的选品（停 0.8 秒）我觉得方向是对的。（停 2 秒）
物流的时效（停 0.8 秒）一直是老大难问题。（停 2 秒）
供应商那边（停 1.5 秒）已经答应缩短交期。（停 2 秒）
商品详情页的优化（停 1.5 秒）下周开始做。（停 2 秒）
以上是这个月的复盘。（停 2 秒）
下一步我们重点盯转化率。

## 录完之后

```bash
# 转格式（每段都要）
npm run normalize -- spike/audio/02-numbers.wav
npm run normalize -- spike/audio/03-mixed.wav
npm run normalize -- spike/audio/04-terms.wav
npm run normalize -- spike/audio/05-pauses.wav
```

同名的 `.txt` 已经放好了，就是上面这些稿子，可以直接当 ground truth。

**只有一种情况需要改 `.txt`**：你念的时候改口了、念错了、或者加了「嗯」「啊」之类的语气词。那种情况下按你**实际说出的内容**改 `.txt`——我们要比对的是 ASR 听错了什么，先自己修正就测不出来了。

## 关于数字的一个坑

`.txt` 里的数字都写成中文（「三千二百件」而不是「3200件」），因为那是你的实际发音。跑准确率时加 `--no-itn` 让 ASR 也输出中文数字，两边口径才对齐：

```bash
npm run probe -- --audio spike/audio/02-numbers-16k.wav --truth spike/audio/02-numbers.txt --no-itn
```

不加 `--no-itn` 的话，ASR 会输出「3200件」，跟 ground truth 的「三千二百件」对不上，CER 会虚高——那不是识别错误，是口径不一致。
